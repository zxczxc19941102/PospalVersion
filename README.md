# 银豹全版本下载链接速查工具

一次性抓取银豹官网「版本升级信息」页（<https://www.pospal.cn/Version.aspx>）全部 **72 个软件分类**的所有历史版本。
左侧选分类、右侧看版本，**点击版本号即复制完整下载链接**，方便直接转发给别人。

提供两个界面，数据与交互完全一致：

| 界面 | 入口 | 说明 |
| --- | --- | --- |
| **桌面 GUI（推荐）** | 双击 `start.bat` 或 `py gui.py` | 原生 Tkinter 窗口，不需要浏览器、不占端口 |
| 网页版 | `python app.py` | 启动后自动弹出浏览器窗口（`http://127.0.0.1:5000`） |

## 一、环境与启动（重要）

本项目目录下自带虚拟环境 `.venv`（已装好依赖）。三种启动方式任选：

```bat
:: 方式 1（最省事）：双击 start.bat，会自动挑选可用的解释器并启动桌面 GUI

:: 方式 2：命令行启动桌面 GUI
.venv\Scripts\python.exe gui.py

:: 方式 3：命令行启动网页版（会自动打开浏览器）
.venv\Scripts\python.exe app.py
.venv\Scripts\python.exe app.py --no-browser   :: 不自动开浏览器
```

如果重新装依赖：

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

> 注意：这台机器上直接敲 `python` 指向的是 Microsoft Store 的占位别名（在
> `%LOCALAPPDATA%\Microsoft\WindowsApps\python.exe`），执行后没有任何输出、退出码 9009，**用不了**。
> 请使用上面写的 `.venv\Scripts\python.exe`，或者 `py`（`C:\Windows\py.exe`）。
> 若依赖缺失，程序会直接提示应该执行哪条安装命令，不会再抛一堆 traceback。

## 二、桌面 GUI 用法

- 顶部：标题 + 抓取进度（`正在抓取 x/72` → `已加载 72/72`）+「刷新」（清空缓存重抓全部）。
- **左栏顶部两个汇总分类**（最左边带 ⬇ 下载图标）：
  - `⬇ 有效链接`：跨 72 个分类汇总**所有带下载链接的版本**（当前 1729 条），运行后**默认选中**；
  - `⬇ 无效链接`：汇总没有下载链接的历史版本（当前 2247 条），**默认隐藏**，点「显示无效链接分类」按钮才出现
    （搜索时例外：搜到就会显示出来）。汇总明细在首次点击时才加载，之后走缓存。
- **左栏搜索框**（在「软件分类（共 72 个 · 成功 72）」下方），支持四种写法：
  | 写法 | 示例 | 命中 |
  | --- | --- | --- |
  | 汉字/英文子串（模糊） | `收银`、`PC版零售` | 所有包含该关键字的分类 |
  | 全字（完整名称） | `PC版零售收银系统` | 该分类 |
  | 汉字拼音首字母 | `bsyxt`、`yht`、`xcxz` | PC版收银系统…、云后台、小程序（新装修模板） |
  | 全拼 | `shouyin`、`pcbanshouyin` | 同上 |
  按 `Esc` 清空搜索。
- 左栏其余 72 个分类：显示「分类名 · 版本数」，当前项高亮；抓取失败的显示红色「加载失败」。
- 右栏：选中分类的全部历史版本（版本号 + 发布时间；汇总分类里还会标注 `← 来源分类`），
  **无下载链接的历史版本显示为灰色、点了会提示「该版本无下载链接」**。
- **单击版本号 = 复制完整下载链接**，右下角出现绿色「复制成功」，2 秒后自动消失。
- 「在新标签打开」按钮：用系统默认浏览器打开该版本链接（`.exe`/`.apk` 直接下载，Mac 页 / App Store 跳转）。
- 下方「更新说明」区域：显示所选版本的更新内容。
- 抓取失败的分类：右栏提示「重新加载」，点击即单独重试，不影响其它分类（结果通过线程安全队列回到界面）。

## 三、网页版用法

启动后浏览器自动打开（如未打开请手动访问 <http://127.0.0.1:5000>）：

- 顶部进度条显示「正在抓取 x/72」，完成后「已加载 72/72」；点任意分类即时出结果（数据已在内存缓存）。
- 点版本号只会复制链接，不会跳转、不会触发下载；剪贴板失败时会自动退化为 `execCommand`，再失败弹框让你手动复制。
- 更新说明默认折叠，点「更新说明 ▸」展开。
- 窗口宽度 < 768px 时自动改为上下堆叠。


## 五、接口（网页版）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 前端页面 |
| GET | `/api/all` | 全部分类与版本数据（抓取未完成时会等待至多 300 秒），附 `summary` 计数、`virtual` 汇总分类元信息、每个分类的 `initials`/`fullpy` 搜索键 |
| GET | `/api/progress` | 抓取进度，如 `{"done":40,"total":72,"ok":39,"error":1,"running":true}` |
| GET | `/api/config` | 当前并发配置，如 `{"workers":32,"max_workers":32}` |
| POST | `/api/config` | 设置下一批抓取并发，JSON body 为 `{"workers":1..32}`；抓取进行中返回 409 |
| GET | `/api/summary?kind=valid\|invalid` | 汇总分类明细（有效链接 / 无效链接），每项带 `category` 字段标明来源分类 |
| GET | `/api/category/<name>` | 单个分类；缓存命中直接返回，失败项会重新抓取（供「点击重试」）；`name` 传「有效链接」「无效链接」时返回汇总数据；也支持 `?name=`，`?force=1` 强制重抓 |
| POST | `/api/refresh` | 清空缓存并重新抓取全部 |

数据结构：

```json
{
  "ready": true,
  "progress": {"done": 72, "total": 72, "ok": 72, "error": 0, "running": false},
  "categories": [
    {
      "name": "PC版收银系统(Beta)",
      "status": "ok",
      "versions": [
        {
          "version": "V4.71.202.5374",
          "url": "https://file.pospal.cn/pospalTouch/pospalTouch_4.71.202.5374.exe",
          "published": "2026-09-20 11:04",
          "notes": ["1.所有行业默认支付3.0", "2.批量库存变更通知和同步方案"]
        }
      ]
    }
  ]
}
```

## 六、实现要点与已知现象

- 抓取并发默认为 **32 线程**（上限常量 `MAX_WORKERS_LIMIT = 32`），网页顶部显示实际并发并支持输入 1–32 后点击「应用」；分类抓取与下载链接检测共用同一线程池，单分类重试也会并行检测。单次请求超时 15 秒，失败重试 2 次并按 1s / 2s 退避；单分类失败不影响其它分类。
- 分类搜索键由后端统一下发：`initials`（汉字取拼音首字母、英文整段保留）与 `fullpy`（全拼），网页版与桌面版行为一致，前端不需要拼音库。
- `pypinyin` 是**可选依赖**：没装时自动退化为内置的 74 条首字母表（覆盖 72 个分类 + 2 个汇总分类），首字母搜索照常可用，仅全拼匹配失效。
- 同一分类只在「刷新」或「重试」时才重新请求，其余情况走内存缓存。
- 数据全部来自实际抓取的 HTML，原样保留版本号与下载链接；不编造、不硬编码。
- 云后台等分类的**早期历史版本**在官网本身就是老结构
  （形如 `<div class="v_number">· 发布于 2016.02.26</div>`，没有单独的时间节点、也没有版本号），
  解析结果会原样呈现该文本，`published` 为空、`url` 为 `null`。
- 本机若装有会接管本地 HTTP 的过滤类软件（如 AdGuard 会向本地页面注入脚本），
  Werkzeug 开发服务器在写完超大响应后立即关闭连接会被重置（客户端报 `ConnectionResetError(10054)`，
  服务端日志仍是 200）。因此 `/api/all` 等大响应做了两件事：gzip 压缩（3.8MB → 约 1.1MB）、
  响应写完后加 0.15 秒收尾停顿；网页端还额外带 4 次自动重试。实测连续 20 次无失败。
